# 验证清单（每张任务卡完成后对照）

## 完成判定（客观门禁，不是"agent 觉得行"）
- [ ] 验收标准逐条可执行验证（命令/测试/截图），非口头确认

## 基础验证（每张卡必做）
- [ ] 语法/类型检查通过（如 node --check / tsc）
- [ ] 相关测试通过（npm test / pytest / 对应框架）
- [ ] 构建/打包通过（如 npm run build）

## Review 五件事（默认怀疑：假设代码是坏的，除非被证明能跑）
- [ ] 超范围改动（是否动了任务卡限制条件禁止的东西）
- [ ] 改错文件（是否动错文件/模块）
- [ ] 接口兼容（对外接口是否被破坏）
- [ ] 异常处理（错误路径/边界是否处理）
- [ ] 可维护性（命名/结构/注释是否合格）

## 功能验证
- [ ] 核心流程按验收标准逐条核对
- [ ] 边界情况（空值/异常/大输入）不崩

## 对抗性评审（大改动另派评审子代理）
- [ ] 评审子代理用全新上下文，只见 diff 和验收标准
- [ ] 反向挑错：遗漏分支、不一致、安全隐患、性能问题

## UI 验证（如涉及前端）
- [ ] 浏览器截图核对布局（无溢出/重叠）
- [ ] 响应式（桌面/平板/手机）

## 熔断与修复预算
- [ ] 卡内：执行器对同一问题重试不超过 3 次（超过即停止并上报）
- [ ] 指挥侧：本卡最多 1 次修复重派；再次 FAIL → 置 `BLOCKED`

## 预算与停止状态
- [ ] `RUN_STATE.md` 计数已更新（Epoch、完成卡数、Repair、子代理数）
- [ ] 若预算耗尽或 Mission 被阻塞：已写 `RUN_STATE.md` 并停止本轮（停止是正常结果，不是失败）

## 收尾
- [ ] 踩坑/教训已写进 AGENTS.md（「别这样做」）
- [ ] 决策已写进 docs/
- [ ] 任务卡状态已更新；客观门禁通过即自动验收（无需逐卡人工签核）
- [ ] 只有在列出的例外情形才升级给人（语义/不可逆/阻塞/预算）
