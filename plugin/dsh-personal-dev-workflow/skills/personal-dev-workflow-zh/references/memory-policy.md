# 记忆与文件职责

目标：**一个事实只存到最合适的地方。** 文件越多不等于记忆越好。

| 信息 | 真相源 | 什么时候写 |
|---|---|---|
| 当前任务目标/验收 | Task Card | 建卡与验收时 |
| 实际代码变化 | Git diff/commit | 自然产生，不重复抄写 |
| bounded 预算/恢复点 | `.agent-state/run-state.json` | 每次状态变化 |
| 长期架构决定 | ADR / docs | 决策需要跨任务解释时 |
| 稳定项目规则/真实教训 | `AGENTS.md` | 同类错误可能复发时 |
| 用户可见版本变化 | `CHANGELOG.md` | 真正可发布/可感知交付 |
| 临时过程记录 | 可选 daily log | 只有项目确实需要审计轨迹时 |

## AGENTS.md

把它当“地图/不变量”，不是开发日记。

只加入 Agent 无法稳定从仓库推导的内容，例如：

- 项目明确不用某项技术；
- 必须保持的接口/架构边界；
- 曾真实发生、容易复发且代价高的错误。

建议保持短小；“100 行”是提醒，不是硬标准。

## 不再强制的行为

- 每张小卡都写 daily log；
- 每个内部重构都写 CHANGELOG；
- 把任务状态同时写 Task Card、日志、CHANGELOG、RUN_STATE 四遍；
- 每次会话结束都往 AGENTS.md 加“教训”。

没有可复用教训时，不写就是正确行为。

## 恢复优先级

新会话恢复时按以下顺序取事实：

1. 当前仓库/Git；
2. Task Card / SPEC；
3. bounded 状态 JSON；
4. ADR/docs/AGENTS；
5. 聊天历史只作为补充，不作为状态数据库。
